# ADR-0010 — Self-contained chapters: readability over reuse

- **Status:** Accepted (2026-10-07). Supersedes the code layout and page-sync parts of ADR-0007.

## Context
ADR-0007 organised the course like a software product. Building blocks lived in a shared package
(`course/lvio_course/`) that grew chapter by chapter, later chapters had to import rather than
reimplement, and chapter pages were assembled from code snippets, captured output and inline metrics
by marker comments.

Reading the first chapter (B01) showed what that costs a learner:
- The equation the chapter is about sat three files away from the chapter, behind `sys.path` edits
  and imports of experiment tooling.
- The page source was fragments glued together by markers.
- Every new chapter would deepen the dependency chain, so chapter 20 could not be studied or modified
  without chapters 1–19.

The repository owner's verdict: nested abstraction "goes against the philosophy of the whole codebase".
A learner who is lost in the plumbing leaves for another source.

## Decision
- **Law 0 (CLAUDE.md §0): a learner can read one chapter alone.** It outranks DRY, generality, speed
  and tooling convenience.
- **One folder per chapter:** `README.md` (the lesson), one `.py` per idea, `main.py`, and `results/`.
  It imports only the standard library, NumPy, SciPy and Matplotlib (plus rosbags for real data), and
  its own files.
- **Copy, don't import.** Shared helpers are duplicated, with a comment naming the chapter they come
  from. A few duplicated lines are the price of independence, and we pay it.
- **The code mirrors the maths:** the README tags equations with `\tag{n}` and the code cites them as
  `(Eq. n)`. Both directions are checked.
- **Hand-written READMEs, no markers.** The one generated link between code and page is replaced by a
  check: `results/output.txt` must appear verbatim in the README, and the chapter test asserts every
  claim from `results/metrics.json`. `tools/sync_course.py` only publishes READMEs to the site and
  generates the course map tables.
- **Visual, intuitive synthetic data:** each chapter's `scene` in `curriculum.yaml`, preferring classic
  teaching examples. Parts D–G share "The Courtyard", regenerated by each chapter's own copy of the
  generator.
- **Enforcement:** `tools/check_chapters.py` runs in CI and the pre-commit hook. It checks imports,
  `sys.path`, inheritance, decorators, file length, equation cross-references, the quoted output, images,
  sections, the test and the nav entry.

## Consequences
- Fixing a bug in a duplicated helper means fixing each copy. That's acceptable: the copies are short,
  the tests catch divergence in behaviour, and a learner can see each chapter's version.
- `course/lvio_course/` and the snippet/output/metric markers are removed.
- `pyproject.toml` installs only `lvx`.
- Chapter pages on the site are build artefacts (git-ignored `docs/learn/<ID>-<slug>/`).
- The experiment harness (`lvx`) is not a teaching artefact, but it follows the same spirit: "explicit
  over clever" (CLAUDE.md §7). A run must be traceable from spec to executed command without hopping
  through layers. Flattening `lvx` accordingly is tracked in ROADMAP (C0.1).
